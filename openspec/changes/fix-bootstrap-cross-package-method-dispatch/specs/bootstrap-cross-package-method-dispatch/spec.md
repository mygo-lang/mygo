## Purpose

Defines that the bootstrap pipeline type-checks and generates buildable Go for
calls to an imported MyGO package's interface/typeclass methods and inherent
impl methods, whether the import resolves to a sibling package in the same
module or to a separate module via `go.mod` `replace`.

## ADDED Requirements

### Requirement: Cross-package interface method calls type-check
When a MyGO package imports another MyGO package and calls an interface or
typeclass method on a value of an imported package type (for example
`concurrency.MakeChan[Int](4)` followed by `ch.Send(7)` / `ch.Receive()`, where
`Send` / `Receive` are declared via `impl ... : Interface` blocks in the
imported package), bootstrap inference SHALL resolve the method through the
imported package's impl/typeclass symbols instead of failing with an
`unknown field` diagnostic.

#### Scenario: A consumer calls an imported channel's interface methods
- **WHEN** a package in module A imports module B's `lib/concurrency` and
  calls `Send`, `Receive`, `Len`, and `Cap` on a value produced by
  `MakeChan[Int]`
- **THEN** bootstrap inference SHALL accept the program and infer each method
  call to the type declared by the imported package's impl

#### Scenario: A sibling package in the same module calls an imported method
- **WHEN** two packages live in the same Go module and one imports the other
  (e.g. `import jsonlib "example.com/mod/jsonlib"` then `doc.Parse(s)`)
- **THEN** bootstrap inference SHALL resolve `Parse` through `jsonlib`'s impl
  symbols without an `unknown field` diagnostic

### Requirement: Cross-package inherent impl method calls type-check
When a MyGO package calls an inherent impl method on a value of an imported
package type (a method declared in an `impl` block with no interface, bound
directly to the nominal type), bootstrap inference SHALL resolve the method
through the imported package's inherent impl symbols.

#### Scenario: A consumer calls an imported struct's inherent method
- **WHEN** a package imports another package and calls a method that the
  imported package declares in an inherent `impl` block on its exported
  struct type
- **THEN** bootstrap inference SHALL accept the program and infer the call
  using the imported package's inherent impl symbol

### Requirement: Generated Go for cross-package method calls is buildable
For every accepted cross-package interface, typeclass, or inherent impl
method call, bootstrap codegen SHALL emit a call to the owning package's
mangled helper qualified by the importing alias (for example
`concurrency.MygoIT13IWritableChan...M4Send`), and SHALL emit the helper's
explicit type arguments when required so the call unifies in Go. The generated
Go SHALL compile with `go build` in the consuming module.

#### Scenario: Generated consumer code builds against the library module
- **WHEN** a consumer package that calls an imported channel's `Send` and
  `Receive` is generated by bootstrap and the consuming module is built with
  `go build`
- **THEN** the build SHALL succeed, with the method calls lowered to
  alias-qualified helper invocations that resolve in the imported package

#### Scenario: No bare unqualified helper is emitted for an imported method
- **WHEN** a cross-package interface method call is lowered to Go
- **THEN** the emitted helper identifier SHALL be qualified with the import
  alias and SHALL NOT be emitted as a bare package-local symbol that is
  undefined in the consuming package
