## Context

The existing generated-output cache is checked after source parsing, dependency traversal, and Go signature population. Importers can need dependency declarations even on a generated-output hit. The emitter prepares global context and selects declarations by scanning the package for each file. See the proposal and capability spec for scope and requirements.

## Goals / Non-Goals

**Goals:** Reduce verified warm-build work and multi-file emission scaling while preserving observable output and making gains measurable. Keep source responsibilities understandable and files manageable.

**Non-Goals:** Change language or generated ABI, weaken cache validation, parallelize the compiler, optimize runtime code, or rewrite the lossless parser.

## Decisions

### Validate a reusable package summary before expensive work

Persist a versioned, integrity-checked summary of dependency discovery and the public source/type information actually required by importers, together with the inputs needed to validate it. A lightweight input fingerprint and dependency-key walk precede full parsing and FFI loading. Only a fully validated summary and output entry permit the early hit; absent or uncertain information takes the existing path. Cache summaries must preserve source positions and test-package distinctions wherever needed, avoid checkout-specific paths, and be published atomically with appropriate locking. Include all relevant MyGO and Go source/module/toolchain/build inputs, replacements and transitive dependencies; where a complete fingerprint cannot be proven, fall back. Do not trust timestamps or a partial import scan as proof.

The implementation must first trace what `bootstrapCollectMyGoPkgInfos` and importers consume, then choose the smallest sufficient representation. Existing entries without compatible summaries are ordinary misses. An alternative of merely moving the existing lookup earlier cannot establish dependency keys or importer metadata, so it is unsafe by itself. Memoizing only Go FFI data is a useful complement but does not avoid parsing on a warm hit.

### Prepare emission context once per package

Build a deterministic ordered index of declarations by source path and prepare package-wide helper, import, type and canonical representation information once. Pass an explicit context to file emission, retaining a compatible single-file entry point if required. Preserve declaration order, synthetic declarations, imports, per-file alias resolution, test files and line-directive behavior. Avoid maps as output iteration sources unless ordering is explicitly preserved. Repeated scans within the same file can be indexed where profiling supports it. The alternative of retaining per-file whole-package filters retains the current scaling cost.

### Measurements and readability guide implementation

Capture pre-change baselines for isolated generation and end-to-end builds, then repeat identical workloads after each optimization. Measure disabled/cold/warm cache, implementation and public signature edits, multiple file counts at controlled total declarations, and Go-toolchain time separately. Use stage timing, allocations and output parity; do not assert a fabricated percentage target. Prefer focused pure transformations, explicit data flow, small named helpers and MyGO `impl`, typeclass, prelude collections or pipes when they improve readability without adding measured hot-path allocation. Split long touched files by coherent responsibility rather than an arbitrary line threshold; keep generated files under the project's established generation workflow.

## Risks / Trade-offs

- [Incomplete cache key or summary hides diagnostics or changes output] → conservative validation, cache-off differential tests, negative tests for every dependency class, and fallback when in doubt.
- [Summary adds I/O, stale versions, or platform issues] → measure cold and warm cases, version and validate records, reuse existing atomic publication and lock contracts, and test corrupt entries and concurrent builds.
- [Per-file indexing changes output order, imports or source mapping] → compare generated bytes across multi-file, external-test, aliases, helpers and line-directive fixtures.
- [Additional abstractions make hot paths slower] → prefer readability with measured allocation costs; keep a simple representation where abstraction adds overhead.

## Migration Plan

Version any new summary independently or bump the cache format as needed. Ignore old or invalid entries and rebuild; cache cleaning remains compatible. Roll back by disabling the fast path or using the previous compiler, with no source migration or persistent repository output required.
