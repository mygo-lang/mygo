## Why

The uncommitted parser2/formatter work corrected the declaration-nesting bug (top-level `func`/`impl` after an `interface` were indented into it) but introduced two layout regressions, and a third defect is shared by HEAD and the working tree: triple-quoted raw strings lose their relative line indentation. `mygo fmt` therefore still cannot round-trip `lib/concurrency/channel.mygo`, and three formatter golden tests fail on the working tree (`TestFormatterIfAndCaseGolden`, `TestFormatterPatternAndMultilineGolden`, `TestFormatterWideControlUsesBlocks`).

Verified by a 2x2 harness bisect of HEAD versus working-tree `zz_*.gen.go` files:

- Regression A (introduced by working-tree parser2): `case ... then ... end` inside `switch` loses its extra indent level and the switch's `end` is displaced, leaving a dangling trailing `end`. Traced to `collectLayoutEvents` discarding whole enter/exit event pairs when `verifiedLayoutAnchor` rejects an anchor, plus `branchEndAnchor` scanning from the `if-then` anchor itself instead of the parent `if`, so a case-body `end` is consumed as the branch exit.
- Regression B (introduced by working-tree parser2): wide single-line `if ... => ... else ...` is no longer expanded into block form; the expansion pass sees no usable events for the construct.
- Bug C (present at HEAD and in the working tree): lines inside triple-quoted strings are re-indented to the enclosing construct's target indent, flattening embedded Go code (e.g. the `code: """..."""` bodies in `lib/concurrency/channel.mygo`).

- Regression D (found while reproducing on `internal/mygo/parser2/lossless.mygo`, present in the working tree): wrapping an over-long line that contains nested single-line delimited constructs (a struct literal inside a struct literal, a call inside a struct field) produces corrupt output — the field label before an inner delimiter and the callee name before a call's argument list are deleted, and each wrapped construct rewrites the whole anchor line so later wraps read already-corrupted text. Minimal repro (formats in <1s via `mygo fmt`, no bootstrap): `{ Ok: true, Consumed: ..., Value: SpannedX { Value: reply.Value, Span: stateSpan(state, reply.State) }, ... }` renders as `{ Ok: true, Consumed: ..., Value: SpannedX {\n Value: reply.Value,\n\n state,\n reply.State,\n ) } }` — `Span:` and `stateSpan(` are gone. This is why `channel.mygo` round-trips but `lossless.mygo` shreds into ~30 garbage comma-lines.

- Regression E (found while formatting the real `internal/mygo/parser2/lossless.mygo`, present in the working tree at the D6 stage): the block/branch/case/delimited passes each mutate a growing text but locate their anchors by the ORIGINAL parser2 line, so a pass whose construct sits below an earlier (upper) `if`/`case`/`block` expansion reads a row those expansions have already shifted downward. Wherever an expansion sits above later expandable content, this drops content and emits orphaned comma- / `)`-only lines — the residual corruption `lossless.mygo` still showed after D6. Fixed by having every pass emit per-expansion line edits and translate each original anchor to its current row before it is read or rewritten (design D8; committed). D6's "leave nested verbatim" was also shown to be non-idempotent on its own; the canonical fix is a recursive `=>`/`then` reflow (design D9).
## What Changes

- Restore correct layout-event production in parser2 lossless for `case` bodies and wide `if`/`case` expansion: anchors are resolved by tracing the actual construct (parent-`if` exit for `if-then` branches, declaration/inline-Go exits retained), and events are never silently discarded when an anchor cannot be verified.
- Make the formatter emit protected regions, in particular triple-quoted (raw) multiline strings, verbatim: every line inside the literal, including its leading whitespace, is reproduced byte-for-byte; no dedent, re-indent, or trimming. Closing-delimiter column is preserved as part of the literal content.
- Make the wrapped-delimited renderer preserve every source byte: only outermost same-line delimited constructs are expanded (spans nested inside another wrapped span are left verbatim as part of their enclosing item text), and item text is taken from the item's own span so no field label or callee name before an inner delimiter is dropped. The wrapped region plus the rest of the file must re-format to a byte-identical second pass (idempotence).
- Make multi-pass reflow coordinate-correct (design D8, committed): every reflow pass emits per-expansion line edits (`SourceLine` + `Added`) and receives the cumulative prior-pass edits, so an original source line is translated to its current row before it is read or rewritten; single-expansion output stays byte-identical to the prior collapsed-edit behaviour.
- Re-architect the reflow core into a recursive inline/block pretty-printer over the lossless span/event model (design D9) so constructs that share one physical line reflow correctly and idempotently: inline `if`/`case` use `=>`, wrapped ones use `then … end`, an expression `if` always carries `else`, and a wrapped `{}`/`[]`/`()` (non-tuple) adds a comma after every item while a single-line one adds none after its last item.
- Land the recursive reflow for arrow-`case` value constructs (M1+M2, committed `e1dceb4`): a `case … => <body>` whose body is a call / value `switch` / value `if` that must expand to more than one row is owned by a single recursive pass and verbatim-locked (byte-exact canonical Example B, and a value `if` case body → Example C), and the flat branch/case/delimited passes are guarded to defer to it. This also fixed a corruption bug where the last delimited item absorbed its closing delimiter (`…))`), which had been emitting invalid mygo; `lossless.mygo` now re-parses on a second `fmt` pass.
- Make the recursive reflow the sole idempotent wrapper for every over-long construct, including statement/expression positions, to reach full-file idempotence (design D10). Two coupled defects block full-`lossless.mygo` idempotence after M2: (A) outermost-only flat wrapping re-wraps nested-but-long spans on the next pass, and (B) the flat pass's per-span target mapping drifts at file scale and drops the wrapped-item indent bump. The cure widens `reflowPass` to own any line whose *value* reflows to >1 row (statement prefixes sliced from parser-owned spans, never a naive scan), verbatim-locks those rows (baked indent → immune to (B); one-pass recursive wrap → immune to (A)), and makes the flat delimited pass skip reflow-authority lines.
- Split the two remaining parser2 event-coverage gaps that block forced block layout (design D11) into two independent, separately-shippable goals and close both: **GOAL A** — `collectExprSpans` `IfExpr` suppresses the `if-else` node span when the else-branch is itself an `if`, so the formatter's `siblingElseLine` cannot close the then-branch at the `else` row and the `else` keyword renders one indent too deep; always emit `if-else` at path `[2]` and re-home a nested `if` else-branch subtree to `[2, 0, …]`. **GOAL B** — `FuncLitExpr` emits no layout event, so a multi-line func-literal body is invisible to the depth engine; emit a `func-lit` node span and an `enter:func-lit`/`exit:func-lit` pair with `AffectsIndent` only for a block (multi-line) body so inline func-literal call chains stay byte-identical.
- Adopt the **single-authority whole-span renderer** (group 16 / design D11+D12) as the chosen path (user-selected option 1) for the two remaining format-quality families, rather than further per-pass patching (15.1/15.4/14.1 each regressed when piecemeal). Both user-reported mis-formats — `tripleQuotedLines` (a statement `if/elsif/…/else/end` chain with a multi-row `elsif` body containing a nested value-`if` must render as a FLAT keyword chain at the source base indent, each branch `+1`, the nested value-`if` block-expanded per R1) and `LosslessProtectedLines` (a `>`-100 nested call that wraps one-arg-per-line must keep its closing `)` at the argument-anchor line's base indent, never column 0) — are pure rendering-authority gaps. The renderer folds the block-vs-inline decision, the indentation, and the surrounding prefix/suffix text into ONE recursive authority (`spanIfRows`/`spanElsifRows`/`spanThenRows`/`spanElseRows` + the delimited close-indent) that owns elsif-bearing statement `if`s, multi-row `then` bodies, and the delimited closing-delimiter base together, so the group-14/15 multi-pass depth-drift family is authored once instead of negotiated between passes. Shipped in dependency order 16.3 (multi-row `then`) → 16.4 (delimited close-indent) → 16.2 (unlock the dormant `spanElsifRows` by relaxing `spanIfEligible`'s `!subtreeElsif` guard) → 16.5 (whole-corpus re-measure), each gated against a golden + the fixed spot-check set (round-trip + idempotence) and reverted on any regression.
- Acceptance anchors: `mygo --bootstrap fmt < lib/concurrency/channel.mygo` is byte-identical to its input, formatter/parser2/cmd tests pass, and the three failing goldens turn green without weakening their expectations.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `formatter-cli`: (1) Parser-owned layout events must remain complete and correctly anchored for `case`, `if`, `else`, and `then` constructs, including `case ... then ... end` bodies inside `switch` and wide single-line conditionals; discarding an event pair for an unverifiable anchor is not permitted. (2) Source-content preservation is strengthened for raw multiline strings: all lines of a triple-quoted literal are reproduced verbatim with their original relative indentation. (3) Wrapped delimited constructs must preserve source content: expanding an over-long delimited construct SHALL NOT delete text that precedes an inner delimiter (field labels, callee names) and SHALL NOT let one wrapped construct corrupt another on the same line; formatting SHALL stay idempotent for files with nested delimited constructs.
- `formatter-cli`: (4) Multi-pass reflow SHALL be coordinate-correct — a construct located by an original source line SHALL be re-read from the row that earlier upper expansions shifted it to, so no content is dropped or relocated and formatting stays idempotent. (5) The formatter SHALL reflow constructs that share one physical line recursively and idempotently: an inline `if`/`case` renders in `=>` arrow form, a wrapped one in `then … end` block form, and a keyword `if`/`case` used as a value inside a delimited construct renders inline in `=>` form (an expression `if` always carries `else`).
