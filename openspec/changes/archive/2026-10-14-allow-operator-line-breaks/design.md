## Context

动机见 proposal.md。生产 parser2 经 ParseSyntaxAt 构建无损 CST，再由 LowerSyntax 生成 AST。parseBinaryTail 已跳过运算符两侧 trivia，但 syntaxStatementEnd 和 syntaxStatementEndBlockAware 只识别行尾二元运算符续行。formatter/syntax_blocks.mygo 另有语句边界判断，普通表达式渲染会将换行压成空格。

## Goals / Non-Goals

**Goals:** 让 CST 成为续行和排版的结构依据；所有表达式位置共享递归断行策略；格式化结果可重新解析且 AST 等价。

**Non-Goals:** 不增加其他行首运算符、不修改运算符集合或结合性、不用文本切割重建表达式、不增加行宽配置。

## Decisions

### 1. 管道前瞻决定语句续行

在现有行尾续行规则之外，换行后的下一个有效 token 为 `|>` 或 `<|` 时继续当前表达式，不检查缩进。跳过空白、空行和注释，但不得越过语句分隔符、声明、分支或块边界。运算符必须有左右操作数；缺失时生成定位诊断并保留恢复区域。

只扩展管道可避免把独立的 `-b` 改成上一行的减法。全局忽略换行会破坏语句边界，因此不采用。parser2 拥有语法判断，formatter 优先消费已分组的表达式节点；必要的原始区域处理复用 parser2 判定，避免维护第二套语法规则。

### 2. 保留管道的断行位置

通过 BinaryExpr 的 token/trivia 和源跨度识别管道前后已有的换行，保留对应操作数与运算符之间的断行关系。续行相对所属语句增加一级（两空格），链上各续行同级，不因左结合树而逐级增加缩进。空白行数量可规范化，注释文本与顺序必须保留。

保留行首和行尾两种管道布局，优先于短表达式压缩；不把所有管道无条件展开。源输入布局是管道排版的显式信号。

### 3. 超长表达式在二元运算符后断行

以现有 100 列首选宽度为预算，包含当前缩进、绑定/赋值/return 前缀、字段标签或条件头。递归从 CST 构造布局候选；优先选择低优先级二元运算符，再按源顺序稳定选择满足预算的断点。自动产生的断点一律位于运算符之后，适用于 `+ - * / == != < <= > >= && || |> <|`，不拆一元运算符或 token。

调用、集合与括号组继续使用既有递归排版，避免新建独立文本重排流程。保留括号和 AST 结构，不重结合浮点算术或混合管道。已有管道断点先固定，剩余过宽片段可进一步按行尾运算符断行。若没有合法断点（如单个长标识符或受保护字面量），允许超过首选宽度；不破坏 token 来满足硬限制。

### 4. 注释与稳定性

将注释作为布局约束，不能使行注释吞掉操作数；字符串及 inline Go 受保护范围不参与断点选择。多行条件必须保留 `then`/箭头与块的归属，不能将条件续行解析成块内语句。自动断行结果在第二次格式化时按同一宽度策略得到相同布局，不能仅依赖固定点循环掩盖振荡或错误输出。

新增手写模块目标不超过 400 行、上限 500 行，避免继续扩大已有大文件。

## Risks / Trade-offs

- [行首管道改变原有语句切分] → 仅识别管道，覆盖块边界和相邻普通语句回归。
- [注释/空行影响前瞻及归属] → 无损往返、注释顺序及恢复定位测试。
- [递归排版误改结合性或条件边界] → 格式化前后 AST 等价验证及混合运算符测试。
- [管道保留规则与宽度排版振荡] → 两次格式化字节相等，覆盖嵌套调用和多处展开的完整文件。
- [不可拆内容超过 100 列] → 明确首选宽度而非硬限制，保留受保护内容。

## Migration Plan

先实现并验证 parser2，再接入 formatter；按 bootstrap 顺序同步相应生成 Go。补充语法文档并运行解析器、格式化器及 CLI 回归。无需数据迁移；回滚时一并还原手写源码和生成产物。
