## Why

Bootstrap 类型推断将 `0i64` 正确识别为 `Int64`，但生成器剥除后缀后输出局部绑定 `count := 0`，导致 Go 将其推断为 `int`。这会使编译器记录的类型与实际 Go 类型不一致，并影响后续函数调用、泛型推断和运行时类型观察。

## What Changes

- 为显式数值后缀生成对应的 Go 有类型表达式，覆盖 `i8/i16/i32/i64`、`u/u8/u16/u32/u64`、`f32/f64`。
- 保证局部 `let`、`var`、表达式及调用实参保留后缀指定的类型。
- 保持无后缀数值的既有行为，并验证显式注解、包级绑定、负数与进制前缀兼容性。
- 使用生成 Go 的类型检查及执行结果验证，补足仅检查 MyGO 推断类型的测试缺口。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `bootstrap-codegen-correctness`: 增加显式数值后缀在 Go 生成结果中的类型保持要求。

## Impact

- 主要涉及 `internal/mygo/codegen2` 的数值表达式生成及其测试，以及对应自举生成文件。
- 复用现有 AST 推断类型与 Go 类型映射；不增加依赖、不改变语法或公共 API。
- 正确生成的局部值将由错误的 Go 默认数值类型恢复为源程序声明的后缀类型；依赖旧错误类型的代码可能暴露原有不匹配。
